# 概述

此文档旨在解释 `vault` 和 `wiki` 的概念与使用方法。

## Agent 的记忆

首先需要明确：
```txt
Agent = Harness + LLM
```
LLM本身是无状态的，只能接受，处理和输出指定格式的信息，如文本，图像等（通常为文本基座）。这种无状态的特性让其在面对简单的文字处理时得心应手。但是，这并不意味着模型的能力是无限的。
让无状态的模型成为有状态的工具，除了训练之外，只能依靠赋予其状态的东西，即上下文。模型能够知晓的信息均在上下文中。然而，上下文是有限的，也就是说，模型的记忆是有限的。
如何拓展记忆呢？

### Compact
大部分的harness中都有这样的一条指令，意为“压缩”。主要的原理就是进行一次单独的llm调用，system prompt大致是“给出摘要”之语。通过无状态的类subagent对原本的上下文进行语意理解，并按照指示压缩原本对话的信息。这当然会破坏KV缓存，但是使得在丢失信息精度的情况下，能够容纳更多的信息。
但是，丢失信息的代价有时是无法接受的，或者模型已经因过长的上下文而丢失了注意力，这种情况下，compact并不是一个很好的选择。可是，各个session之间的信息并不互通。虽然说 Swarm 可以建立一套沟通渠道，但是对于动辄上百个对话的用户而言，可能比较复杂，而且依靠代码建立的渠道过于僵硬。

### Skills
将部分文本（代码）精炼，生成skills，并在运行过程中动态调用
这是很精妙的设计，通过标准的注册表拓展的模型的能力，但是又不会过分的影响到模型的上下文。主要依靠的就是：简短描述+动态调用。
Skills的存在在确保几乎没有注意力污染的情况下，大大拓展了模型上下文**可能容纳的信息**。虽然模型并没有真的“记住”了这些信息，但是在 *skills库* + *按需索取* 的机制下，库本身就成为了记忆的一部分。

### AGENTS.md
有一种特殊的项目文件，叫做 AGENTS.md，或者是 CLAUDE.md。此类文件会在所有项目下的agent初始化的时候填入system prompt中。这实际上是一种个性化的系统提示词，自然能够起到跨sessions记忆的作用

其他类似的记忆方法，不过多叙述。

## vault wiki
不难看出，如果要拓展agent的记忆，那就一定要突破session的上下文。如何实现呢？采用 **vault + wiki** 的方法


简单来说，vault-wiki是为agent特化的通用跨session记忆系统。其中，vault的主要目的是容纳，而wiki的目的是整理。
