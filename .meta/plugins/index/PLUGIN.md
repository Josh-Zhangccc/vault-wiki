# index：索引

派生层聚合页：检索的便宜入口（query 命令的第二层）。溢出减负制：索引诞生于上级的减负需要，而非目录的「应该承担」——小库全部内容直列根索引一张走天下，内容长大到哪里，披露边界就出现在哪里。

## Structure

- 根 `wiki/index.md` 恒在：format_version frontmatter（页面格式契约版本，不兼容变更时进位）——根索引即版本自述处；直列可达页面（本目录 + 未切子树，全路径 wikilink）
- 其余目录 `index.md` 按溢出减负诞生：某索引清单（页条目 + 目录条目）超窗时，按子树页数降序（同数按名序）切出子目录自立索引，直至装下；递归适用
- 条目 = wikilink + 描述（frontmatter `description` 优先，缺失取正文首个非空非结构行截 80 字）；概念页按 type 分组；切出子目录入口行带子树计数；空子树（0 页）保留一行可见性（无链接，不入断链图）
- `wiki/tags.md`：tag → 页面反向索引（聚合 tag 插件的字段）

## Invariants

- 索引页全部可再生、永不手编：只聚合、不原创；纯函数重建——减负切分是结构现状的函数，同结构必同结果，无历史状态
- 窗口参数以 `pipeline.py` 源码为准（脚本源码即规则清单）；并回上级后多余的旧索引随重建机械删除
- 索引不发明结构：索引的存在与内容只反映结构，永不暗示目录该怎么组织；本级平铺文件超窗时如实超窗，分目录属人 / 领地插件
- 与实际页面集一致；保留名文件（index / log）、wiki 根派生页（hot / tags）、archive/ 子树不视为概念页、不入索引
