# 指针：信息披露的挂载机制

> 设计档案（2026-09-14 成文，设计讨论蒸馏）：指针是 vault-wiki 的核心架构概念，早已散落于系统各处，2026-09-14 显式化命名。非实例运行件；机制实现以 `.meta/` 为源。

## 为什么需要指针

新 session 按 SASU-L（system prompt → AGENTS.md → Skills → 用户原话 → loop）获取信息：system prompt 不携带库内信息，AGENTS.md 与 Skills 是静态披露，用户默认新 session 已知（不可能）——**跨 session 的信息获取只能依靠 L：agent 主动读取**。没有路标的 L 是盲的：全读则上下文爆炸，漏读则信息失联。指针把 L 从盲目扫描变成条件化挂载。

## 定义

**指针 = 常驻上下文的低成本路标，把「何时读什么、读完做什么」压缩进一行，让 L 层按条件精准挂载更大的信息体。** 它是渐进披露的第一层：指针常驻（占极小上下文）→ 指向物按需读取 → 指向物的引用物再下钻（index 逐层下钻即此结构）。

## 构成

必有件（缺一不成指针）：

- **位置**：指向哪里——机器可解析（路径可检查存在性，断链扫描本质就是指针健康检查）
- **概述**：指向什么——让 agent 不打开就能判断要不要跟进；这是指针筛选效率的全部来源

可选件（按指针类型取舍）：

- **触发条件**：何时激活——有它为**主动型**（条件满足即挂载），无它为**被动型**（被问才用）；最重要的可选件
- **处理方式**：读法（只读参考 / 按序执行 / 聚合呈现）——多数指针隐含「读即用」，复杂者须显式
- **触发后行动**：读完干什么（提醒 / 执行 / 汇报 / 回写）——当行动 ≠ 读，必须写明，否则挂载了也不知所措

系统性两件（跨指针的全局纪律）：

- **维护责任**：手写指针会烂（指向物被移动、描述过时），需更新纪律（「指针需主动更新」）与健康检查（断链 warning）；派生指针机械再生成、免疫腐烂，代价是投影纪律
- **容量预算**：指针自身占上下文，价值 = 概述的筛选效率 ÷ 指针区膨胀；指针区必须有行数纪律（AGENTS <150 行、注入行单行，都是此预算的实例）

## 系统中的指针实例

| 指针 | 位置 → 指向 | 维护 | 触发 |
|---|---|---|---|
| AGENTS 指针区 | AGENTS.md → 各文档 | 手写 | 被动（ATTENTION 标注提高优先级） |
| 插件注入行 | 注入区 → 插件页面与纪律 | 派生（manifest） | 多为主动（携带「何时先读」条件） |
| wiki/vault 代理层 | 代理页 → vault 资产（raw_file / raw_sha256） | 派生（map） | 被动 |
| index / tags | 目录索引 → 页面集 | 派生（pipeline） | 被动（检索逐层下钻） |
| hot | 热缓存 → 最近变更 | 派生（pipeline） | 主动（进库先读） |
| wikilink | 页面 → 页面 | 手写 | 被动（断链受检） |
| consumes / cmd-inject | 命令 → 插件写侧契约 | 派生（manifest） | 主动（命令触发即加载） |
| registry | 字段注册表 → 值集锚点 | 协议+派生 | 主动（写前一次读取） |
| todo 注入行 | 注入区 → wiki/todo.md | 派生（manifest） | 主动（新 session 先读、到期主动提醒） |

todo 是**时间维指针**的显式实例：指向「未来某时该想起什么」——受托即写下「何时读到此条则行动」，agent 是指针执行器；其余指针为空间维（指向哪里的信息）。

## 新指针设计清单

1. 五件配齐：位置 + 概述必有；触发、处理、行动按需——**触发与行动必须配对**（有触发无行动 = 挂载后不知所措）
2. 选维护路线：能派生不手写（免疫腐烂）；手写须配健康检查
3. 守容量预算：进指针区前先问能否复用既有指针
4. 主动型优先：披露的终极目的不是「可被找到」，而是「该想起时被想起」
