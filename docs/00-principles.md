# 普世定义与设计原则

> 本文档沉淀 2026-08-25 ~ 08-28 系列讨论的收敛结论，是整套框架的上游。下游产出（skeleton / skills / scripts）与本文冲突时，先改本文、再改下游。

## 一、定义

- **vault**：把任意格式的信息存储为资产的容器。包罗万象——md、文本类、结构化数据、静态二进制（pdf / 图像 / 3d）、音视频、其他，都应能进入。
- **wiki**：信息 → md 解析的管道。md 是人与 agent 的公共语言；解析使信息可计算、可见。
- **个性化**：跑在静态骨架上的动态内容与配置（日记体系、素材偏好、称呼规则……），不属于架构。

推论：**静态架构对所有实例同一套；实例之间只差动态层与内容。**

## 二、资产流水线

存储 → 资产不是一步，是一条流水线，每站是一个工位：

**进入（任意格式）→ 存（原文层，丢不了）→ 解析（md 代理，算得动）→ 索引（找得回）→ 沉淀（沉得下）→ 重组（用得出）**

- 后三站（索引 / 沉淀 / 重组）是普遍缺口，定位为管道的**固有工位**，不是可选增强。
- 流水线之上有一条运营约束：**不打架**（多写者治理，见六.1）。

## 三、分层语义

| 层 | 语义 | 关键规则 |
|----|------|----------|
| 原文层 | 格式无关的原始资产，永不可改 | 完整性以哈希登记 |
| 代理层 | 每个资产在 md 世界的代理：摘要 / 转写 / 元数据 / 链接 | 没有代理的资产等于没存 |
| 架构层 | 实例宪法 + 准则 + 技能，静态骨架 | 全实例同一套；个性化只以指针存在 |

## 四、格式与解析器

架构不枚举格式，只设**格式 → 解析器注册表**。新增一种格式 = 注册表加一行 + 一个解析器，架构不动。

| 格式类 | 解析路径 |
|--------|---------|
| md | 直通 |
| 文本类（txt / 代码 / csv） | 轻包装 / 表格化 |
| 结构化（xlsx / json） | 转 md 表 |
| 静态二进制（pdf / 图像 / 3d） | 抽取 / OCR / 描述 |
| 音视频 | 转写 |

## 五、工具可替换性

md + 纯文件是公共底座；Obsidian、agent、WebUI 都是底座之上的 viewer，谁都可以被替换。**架构不得含任何工具私有格式。**（个人库 .components 的退役即此原则的一次应用。）

## 六、运营原则（对实例普适）

1. **单写者 + 写权限分区**：机器管道区（代理层正文与索引）只由管道写，其余设备只读镜像；人类采集区（日记 / inbox / 手工画布）双向。冲突治理：把冲突面收敛到低冲突形态（一天一文件、只增不改），冲突文件由健康检查检出。
2. **文档先行**：准则是仓库内文档，技能退化为「路由 + 读文档」的薄壳；技能与准则冲突时，以准则为准。
3. **发现机制三层冗余**：宪法指针（保底）→ 技能第一步读准则（常态）→ 准则注册表（人类侧）；未登记视为不存在。
4. **宪法近全通用**：实例宪法几乎全通用，个性化只以指针指向实例配置（如 `.vault-meta/`）。
