# 普世定义与设计原则


## 一、定义

- **vault**：把任意格式的信息存储为资产的容器。包罗万象——md、文本类、结构化数据、静态二进制（pdf / 图像 / 3d）、音视频、其他，都应能进入。
- **wiki**：信息 → md 解析的管道。md 是人与 agent 的公共语言；解析使信息可计算、可见。
- **个性化**：跑在静态骨架上的动态内容与配置（日记体系、素材偏好、称呼规则……），不属于架构。

推论：**静态架构对所有实例同一套；实例之间只差动态层与内容。**

## 二、资产流水线

存储 → 资产不是一步，是一条流水线，每站是一个工位：

**进入（任意格式）→ 存（原文层vault）→ 解析（md 代理，进入wiki）→ 索引（wiki检索）→ 沉淀 → 重组**

- 后三站（索引 / 沉淀 / 重组）是普遍缺口，定位为管道的**固有工位**，不是可选增强。


## 三、分层语义

| 层 | 语义 | 关键规则 |
|----|------|----------|
| 原文层 | 格式无关的原始资产，永不可改 | 完整性以哈希登记 |
| 代理层 | 每个资产在 md 世界的代理：摘要 / 转写 / 元数据 / 链接 | 没有代理的资产等于没存 |
| 架构层 | 实例宪法 + 准则 + 技能，静态骨架 | 全实例同一套；个性化只以指针存在 |

## 四、格式与解析器

架构不枚举格式，只设**格式 → 解析器注册表**。新增一种格式 = 注册表加一行 + 一个解析器，架构不动。

| 格式类 | 解析路径 |
|--------|---------|
| md | 直通 |
| 文本类（txt / 代码 / csv） | 轻包装 / 表格化 |
| 结构化（xlsx / json） | 转 md 表 |
| 静态二进制（pdf / 图像 / 3d） | 抽取 / OCR / 描述 |
| 音视频 | 转写 |

## 五、工具可替换性

md + 纯文件是公共底座；Obsidian、agent、WebUI 都是底座之上的 viewer，谁都可以被替换。**架构不得含任何工具私有格式。**
